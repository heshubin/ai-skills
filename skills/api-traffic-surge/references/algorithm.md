# 算法与边界

## 窗口和比较

- 时间字段默认 `@timestamp`，消息字段默认 `message`，都可配置。
- 默认近24小时：以 ES 服务器时间向下对齐至半小时为窗口终点，往前取48个完整桶。例如 +08:00 的17:05运行，统计昨天17:00至今天17:00，不含17:00–17:30。
- 对比图使用 Kibana 选择的起止时间，分别向下对齐。查询会额外向前169小时，保证最左桶的第7天基线也完整；未完成的末桶不展示。
- 每桶基线是该桶前1、2、…、7天同一时段的7个值，包含合法零值。上周同期是第7个值；环比是前半小时，跨日也连续。
- 固定偏移时区保证1天为24小时。支持 UTC、+08:00、+05:30等；不支持夏令时/IANA地区名。

## 判定

`μ = Σx / 7`，`σ = sqrt(Σ(x−μ)² / 7)`，`peak = max(x)`。

满足以下三项才标记：

1. 当前量 **严格大于** `μ + surge_k×σ`（默认k=3）；
2. 当前量 **严格大于** `peak×peak_ratio`（默认2）；
3. 当前量 **大于或等于** `surge_min_count`（默认200）。

若7个历史值全零，且历史覆盖齐全，当前达到最低量即标记。不存在“比峰值恰好多2倍也算”的边界例外。

## 数据可用性

- ES响应必须 `timed_out=false` 且 `_shards.failed=0`，所需聚合和实际桶不能缺失。失败不是0次调用，也不是“没有突增”。
- 每个历史半小时桶必须存在，且其自然日内该服务必须有Request URL源日志。否则基线不完整，不判突增，均值/峰值参考留空；上周参考值只有当天源日志可用时才展示。
- 此覆盖检查不能发现日内局部漏采。重要监控需另接独立采集健康检查；不要仅凭全零就认定业务无调用。
- 历史零桶由ES扩展边界保留；正常低流量接口不因自己某天无调用而被当成服务日志缺失。

## 同比和环比

`(当前 / 参考 − 1)×100%`，仅展示，不参与突增判定。

参考大于0时给百分比；参考为0且当前大于0时显示“新增”；两者都0显示“—”；参考数据缺失显示缺失，不制造0%。API JSON 用 `percent=null` 和 status 区分这些状态。

## 配置一致性与限制

Python统计与Vega模板共享同一配置。修改JSON后需要重新生成/更新看板，现有看板不读取本地配置，不承诺热更新。默认参数固定为3/2/200，两端均会随配置变化。

规则判断的是日志调用量异常，不证明接口失败、业务损失或攻击。没有固定误报率保证，阈值需结合实际数据验证。
