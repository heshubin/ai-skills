# 线上问题排查指南

排查线上问题、分析异常告警时使用。定义标准排查流程和常用工具。

## 触发场景

- 收到线上告警或异常报告
- 排查接口超时、数据不一致、服务异常等问题
- 提到"线上问题"、"排查"、"告警"、"异常"、"故障"时

## 标准排查流程

```
1. 确认影响范围 → 2. 查日志定位 → 3. 数据库验证 → 4. 根因分析 → 5. 修复方案
```

### 第一步：确认影响范围

- 影响哪些用户/仓库/订单？
- 是全量还是部分？
- 什么时间开始的？
- 是否有近期发布或配置变更？

### 第二步：查日志定位

Kibana 日志查询模板：
```
# 按服务查询
index: k8s-central-wms-service-log-*
query: "关键字" AND level:ERROR

# 按订单号追踪
index: k8s-central-*-log-*
query: "订单号"

# 按时间范围
时间选择器设置为问题发生前后 30 分钟
```

关键日志关注点：
- ERROR/WARN 级别日志
- 异常堆栈中的 Caused by
- 请求入参和响应结果
- SQL 执行耗时

### 第三步：数据库验证

```sql
-- 检查数据状态是否正确
SELECT * FROM yamibuy_wh.目标表
WHERE 业务条件 ORDER BY rec_id DESC LIMIT 10;

-- 检查数据时间线
SELECT rec_id, in_dtm, edit_dtm, status
FROM yamibuy_wh.目标表
WHERE 业务条件
ORDER BY edit_dtm DESC;

-- 检查关联数据一致性
SELECT a.字段, b.字段
FROM yamibuy_wh.表A a
LEFT JOIN yamibuy_wh.表B b ON a.关联字段 = b.关联字段
WHERE a.业务条件;
```

### 第四步：根因分析

常见故障模式：

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 接口超时 | 慢 SQL / 死锁 / 外部服务超时 | 查慢查询日志、锁等待 |
| 数据不一致 | 事务未提交 / 并发竞争 / 部分失败 | 检查事务边界、并发控制 |
| 空指针异常 | 数据缺失 / 接口返回 null | 检查数据完整性、null 判断 |
| 重复数据 | 幂等性缺失 / 重试导致 | 检查唯一约束、幂等机制 |
| 服务不可用 | OOM / 连接池耗尽 / Pod 重启 | 查 Grafana 监控、K8s 事件 |

### 第五步：修复方案

- 紧急修复：数据修补 SQL（必须先在 QC 环境验证）
- 代码修复：修复 → 本地测试 → QC 验证 → 上线
- 配置修复：Apollo 配置变更（注意灰度发布）

## 排查工具清单

| 工具 | 用途 |
|------|------|
| Kibana | 日志搜索和分析 |
| Grafana | 监控指标和告警 |
| MySQL 客户端 | 数据验证和修补 |
| Apollo | 配置查看和变更 |
| K8s Dashboard | Pod 状态和事件 |

## 注意事项

- 线上数据修补 SQL 必须先备份、再执行、后验证
- UPDATE/DELETE 操作必须带 WHERE 条件，先 SELECT 确认影响行数
- 修复后持续观察 15-30 分钟，确认问题不再复现
