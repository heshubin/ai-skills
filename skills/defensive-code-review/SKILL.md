# Skill: 防御代码审查

## 触发场景
- 发现一段校验/防御代码逻辑不清晰，不确定是否该删
- 新需求与某段老校验冲突，需要判断是修改校验还是删除它
- Code Review 时发现重复校验，需要确认哪个是真正有效的
- 重构时需要清理"空转代码"（从未被触发的校验）

## 使用方式
把需要审查的代码片段发给我，告诉我：
1. 这段代码在哪个方法里（方法名）
2. 这个方法被哪些路径调用（知道的话）
3. 遇到了什么问题（可选）

---

## 审查框架：防御代码三问

### Q1：它防御的场景真的会发生吗？
分析该校验保护的是哪种异常状态，这种状态在正常业务流程中是否可能出现。

```
判断依据：
- 追踪所有可能写入该字段/改变该状态的代码路径
- 确认在正常调用链中，执行到该校验时字段的值是什么
- 如果所有正常路径都不会触发该校验 → "空转代码"
```

### Q2：它防御的场景是否已被其他校验覆盖？
如果场景真的存在，查找同一方法或调用链中是否有等效的校验。

```
等效校验的识别：
- 保护同一业务不变量（如"任务已完成的不能再操作"）
- 但使用不同的判断依据（status vs 字段内容）
- 两者同时成立时只需要保留更稳定的那个
```

### Q3：判断依据是否稳定？

| 类型 | 稳定性 | 建议 |
|------|--------|------|
| 状态枚举字段（status、park_type） | 高 | 优先使用 |
| 字段是否为空（isNotEmpty） | 中 | 可用，但注意字段复用风险 |
| 字段内容字符串匹配 | 低 | 重构为枚举判断 |

## 输出结论

### 结论A：删除
```
适用条件：
- Q1: 场景不会发生（空转代码）
- 或 Q2: 场景已被其他校验覆盖（冗余代码）

输出：
- 说明为什么可以安全删除
- 确认删除后所有路径的行为不变
```

### 结论B：保留（可选重构）
```
适用条件：
- Q1: 场景真实存在
- Q2: 没有其他等效校验
- Q3: 判断依据稳定

输出：
- 说明保护的是哪个业务不变量
- 如果判断依据不稳定，给出重构为枚举判断的方案
```

### 结论C：修改（补丁方案）
```
适用条件：
- 场景真实存在且需要保留
- 但新需求引入了合法的例外情况

输出：
- 用更精确的条件替代原有宽泛条件
- 明确标注这是"临时修复"还是"最优解"
- 如果是临时修复，记录技术债
```

## 真实案例

**案例：`dealGenPickingFinish` 中的 `parking_slot` 校验**

```java
// 待审查代码
if (StringUtils.isNotEmpty(dbPickingCart.getParking_slot())) {
    throw new YamibuyException(THIS_PICKCART_STATUS_IS_INVALID, ...);
}
```

**Q1 分析：**
- 该校验在 `pickingTaskFinishForPw`（PW完成）和 `pickingTaskFinish`（Batch完成）两条路径中被共用
- PW 路径：拣完扫 COMPLETE，PW 流程不写 `parking_slot` → 始终为空，校验从不触发
- Batch 路径：拣完推停车场写 `parking_slot`，但这发生在 `dealGenPickingFinish` 之后 → 调用时也为空
- **结论：Zone Picking 之前，场景从未发生过，是空转代码**

**Q2 分析：**
- Cart 停入停车场后 `status` 必然不是 `OCCUPY`
- 下方已有：`if (status != OCCUPY || taskStatus != PICKING) → throw`
- 两个校验保护同一边界（禁止对已完成的 Cart 重复提交）
- **结论：场景已被 status 校验覆盖，冗余**

**Q3：不需要分析（Q2 已确认冗余）**

**最终结论：删除**
```java
// 删除后的 dealGenPickingFinish
private void dealGenPickingFinish(...) {
    if (dbPickingCart == null) { throw ... }
    // parking_slot 校验已删除：Q2 确认冗余，status 校验已完全覆盖
    if (status != OCCUPY || taskStatus != PICKING) { throw ... }
    task.status = FINISH;
}
```

**为什么不选修改（补丁方案）：**
- 补丁方案（`park_type != CONSOLIDATION_SLOT` 条件）是在冗余代码上打补丁
- 每增加一种停放类型就要再改一次条件，会持续腐化
- 删除才是根治
