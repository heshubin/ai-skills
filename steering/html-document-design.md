# HTML 文档生成规则

将 Markdown 设计文档/方案文档转为高品质单文件 HTML 展示页面时使用。

## 核心原则

- **信息完整** — 源 Markdown 中所有核心内容必须在 HTML 中完整体现，可增不可减
- **可视化优先** — 用 CSS 图表、流程图、卡片替代纯文字列表
- **视觉专业** — 追求商务级视觉效果，拒绝千篇一律的 AI 审美

## 页面结构模板

```
全屏 Hero（深色背景 + 渐变标题 + 关键数字统计卡片）
├── Section（交替浅色/白色背景）
│   └── 小字标签 + 大标题 + 描述文字 + 具体内容
├── Section ...
└── 深色结论区收尾（数据卡片 + 总结）
```

每个 Section 使用一致的内边距和最大宽度（建议 `max-width: 1200px; margin: 0 auto`）。

## 排版与样式

| 项目 | 规范 |
|------|------|
| 中文字体 | `Noto Sans SC`（Google Fonts CDN） |
| 代码字体 | `JetBrains Mono` 等宽字体 |
| 字号层次 | Hero 标题 ≥ 2.5rem，Section 标题 ≥ 1.8rem，正文 1rem |
| 色彩管理 | 全部通过 `:root` CSS 变量定义，便于主题统一 |
| 间距节奏 | Section 间距 4-6rem，卡片间距 1.5-2rem |
| 正文背景 | 浅色系，确保文字对比度 ≥ 4.5:1 |

## 可视化规范

### 架构图与流程图

使用纯 CSS + HTML `div` 构建，节点样式：`border` + `border-radius` + `background` + `box-shadow`。

- 节点内容分行展示：标题行、描述行、功能列表各占独立行
- 节点最小宽度 180px，内边距 ≥ 1rem，给足呼吸空间
- 语义色彩：绿=正常/安全，橙=警告/降级，红=危险/阻断，蓝=信息，紫=目标
- 连接线用 CSS `border`、伪元素 `::before`/`::after`、或 flexbox gap 暗示关系

### 对比表格

- 使用 `<table>` + 斑马纹（`:nth-child(even)` 背景色）
- 推荐方案行高亮（左侧色条或背景色标注）
- 评分列使用色彩编码或进度条可视化

### 代码块与文件树

- 使用 `<pre><code>` 标签，必须设置 `white-space: pre; overflow-x: auto`
- 深色背景 + 浅色文字，模拟终端风格
- 文件树中用不同颜色区分目录名、文件名、注释

## 交互与动画

- 滚动渐入：`IntersectionObserver` + `opacity`/`translateY` 过渡
- 卡片 hover：`transform: translateY(-4px)` + 加深 `box-shadow`
- 列表项 hover：`transform: translateX(8px)` 滑入效果
- 过渡时长统一 `0.3s ease`，动画克制，重质感不重数量

## 生成前对照检查

逐项核对源 Markdown，确认以下内容已覆盖（仅检查源文档中实际存在的部分）：

- [ ] 背景/目标/问题描述
- [ ] 方案对比表（带评分或推荐标记）
- [ ] 架构图（纯 CSS 可视化）
- [ ] 状态机/流程图（纯 CSS 可视化）
- [ ] 规则列表/安全防线
- [ ] 场景验证/用例表
- [ ] 文件结构/技术实现细节
- [ ] 实施计划/时间线
- [ ] 与其他系统/方案的关系
- [ ] 结论区（关键数据卡片）

## 禁止事项

- **禁止 ASCII 字符画** — 浏览器等宽对齐不可靠，必须用 CSS 节点图
- **禁止引入外部 JS 库**（Mermaid、D3、Chart.js 等）— 所有可视化纯 CSS/HTML 实现
- **禁止内容缺失** — HTML 输出的信息量不得少于源 Markdown
- **禁止泛滥 AI 审美** — 不用紫色渐变 + 白底 + Inter 字体的模板化风格
- **禁止节点内容挤行** — 架构图节点中每个功能点必须独占一行
- **禁止代码块丢失格式** — `<pre>` 必须包含 `white-space: pre`
- **禁止多文件输出** — 产出为单个自包含 HTML 文件（CSS 内联于 `<style>` 标签）
