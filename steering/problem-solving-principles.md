# 问题解决原则

从实际开发中总结的经验教训，适用于所有项目。

## 1. 先试后判断

**禁止基于假设放弃方案。** 必须先实际测试，再下结论。

反面案例：假设 kiro-cli 不能处理图片 → 浪费时间找 Claude API Key 替代方案 → 实际上 kiro-cli 通过 readFile 工具可以读取图片并分析。

正确做法：先试一下，不行再找替代方案。

## 2. 先抓真实数据，再写代码

**禁止猜测外部系统的数据格式。** 必须先获取真实数据，再编写解析逻辑。

方法：
- 添加调试日志打印完整的原始数据
- 从日志中获取真实的 JSON 结构
- 根据真实数据编写解析代码

反面案例：假设企业微信图片消息有 `media_id` 字段 → 实际上是 `image.url` + `image.aeskey`。

## 3. 解决问题，不要规避问题

**规避方案必须标记为技术债务。** 不能把规避当作已解决。

- 如果用了 workaround（如重定向 stderr），必须在 steering 中记录根因和正确修复方向
- 代码中添加注释说明这是临时方案
- 后续有时间要回来修复根因

## 4. 流式消息交互原则

企业微信流式消息（`send_stream`）的使用规范：

- **全程复用同一个 stream_id** — 从开始到结束只有一条消息在变化
- **每个阶段更新提示** — 下载中 → 处理中 → 分析中 → 最终结果
- **错误也要替换** — 出错时用 `finish=True` 替换占位消息，不要用 `send_text` 额外发一条
- **不要残留占位消息** — 所有分支（成功/失败/超时）都必须结束流式消息

## 5. AES 加密媒体文件处理

企业微信 AI 机器人的媒体文件（图片/视频）都是 AES-256-CBC 加密的：

- aeskey 是 Base64 编码（43字符），需要补齐 `=` padding 再解码
- 加密数据前 16 字节是 IV
- 解密后需要补回文件头（企业微信加密前去掉了前 16 字节）
- PNG 图片：补回 `89504E47 0D0A1A0A`（签名）+ `0000000D 49484452`（IHDR header）
- MP4 视频：补回 ftyp box header，需要计算正确的 size

## 6. kiro-cli 图片/视频分析

kiro-cli 可以分析图片和视频关键帧：

- 将文件保存到本地
- Windows 路径转 WSL 路径（`D:\` → `/mnt/d/`）
- 构建 prompt 包含文件路径，让 kiro-cli 用 readFile 工具读取
- 必须走 `_call_kiro_cli()`，不能走 `_local_chat_reply()`
- 图片分析结果用 `_clean_output_light()` 清理（不要用 `_clean_output`，会过度清理）

## 7. 用户体验原则

- 机器人要有人格（Wi.Beta，William 的 AI 助理）
- 回复要友好，不要生硬拒绝
- 不支持的功能要说明支持什么，引导用户
- emoji 要适度，不要用奇怪的组合
- 耗时信息简洁（`⏱ 耗时 Xs`），不要加多余装饰
