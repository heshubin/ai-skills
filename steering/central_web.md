# React + Ant Design 中后台反模式清单

> 适用范围：仅适用 React + Ant Design Web 中后台；React Native 项目（如 central-picking-app、WMS-front-end/wms-rn）忽略本文件。

以下条目定位为“反模式默认禁止”，用于约束代码质量并减少维护成本。
如有充分业务理由可例外，但需在 PR 中说明原因与影响范围。

## 组件与文件组织

1. **禁止组件文件名与组件名不一致** — 组件文件使用 PascalCase，如 `ReservationCard.tsx`。
2. **禁止新增 class 组件** — 统一使用 function 组件。
3. **禁止组件缺少 Props 类型定义** — 使用 `type` 或 `interface`，保持可读和可维护。
4. **禁止可复用表单组件不兼容受控模式** — 对接 `Form.Item` 的组件需支持 `value` + `onChange`。
5. **禁止复用 DOM 原生属性名表达不同语义** — 避免将 `style`、`className`、`onClick` 用于非原生语义。
6. **禁止在入口文件堆砌业务逻辑** — 入口文件仅负责装配、路由和 Provider。
7. **禁止在单个组件持续叠加多块独立业务** — 功能边界变模糊时应拆分子组件。
8. **禁止新增 props 不同步更新类型定义** — Props 类型与实现保持一致。

## 状态与数据流

9. **禁止将纯派生数据存入 state** — 派生值应在渲染流程或 `useMemo` 中计算。
10. **禁止无必要的 props → state 同步** — 降低双源数据和状态漂移风险。
11. **禁止组件内状态职责不清** — 状态明显膨胀时按职责拆分组件或抽取 hook。
12. **禁止组件直接调用底层 HTTP 客户端** — 通过页面 service 或 `src/api/` 统一封装。
13. **禁止修改查询条件但不同步更新参数类型/默认值** — 保证查询行为可预测。

## TypeScript / JavaScript

14. **禁止使用 `var`** — 使用 `const`（优先）或 `let`。
15. **禁止使用 `==`、`!=`** — 使用 `===`、`!==`。
16. **禁止滥用 `any`** — 优先精确类型、泛型或 `unknown`；必要时标注理由。
17. **禁止使用 `@ts-ignore`** — 优先修复类型问题，确需跳过时用 `@ts-expect-error` 并说明原因。
18. **禁止数组使用 `for...in` 遍历** — 使用 `for...of`、`map`、`forEach`。
19. **禁止参数重赋值（reassign）** — 需要修改时创建局部变量。
20. **禁止多层嵌套三元表达式** — 使用 `if/else` 或提取函数。
21. **禁止定时器不清理** — 在卸载或逻辑结束时清理 `setTimeout`/`setInterval`。
22. **禁止 `new Promise(async ...)` 反模式** — 避免多余 Promise 包装。
23. **禁止在 `catch` 中吞掉错误上下文** — 记录或透传原始错误信息。

## i18n 与体验

24. **禁止用户可见文案硬编码** — 使用 `t()` 或`<T/>`项目统一 i18n 组件。
25. **禁止新增页面不补充对应 i18n 文案文件** — 保持模块化命名与可维护性。
26. **禁止通过 localStorage 直接判定当前语言** — 使用 i18n 上下文（如 `useTranslation` / `i18n.language`）。

## 性能与工程化

27. **禁止在渲染中反复创建可静态化的大对象/大数组** — 将稳定结构提到组件外或 `useMemo`。
28. **禁止通过 `window.xxx` 挂载全局能力** — 优先使用模块化导出。
29. **禁止新增 `.js/.jsx` 文件** — 新增代码统一 `.ts/.tsx`。
30. **禁止页面级类型/常量散落在多个组件中** — 按模块集中管理（如 `type.ts`、`constants.ts`）。

## 第三方依赖

31. **禁止引入与现有能力重复的库** — 新增依赖前先检查 `package.json`。
32. **禁止为小功能引入重型依赖** — 优先复用现有工具或按需引入。
33. **禁止引入无类型支持且难以补齐类型的库** — 至少保证核心调用具备可维护的类型约束。
34. **禁止引入已废弃或存在明确高风险漏洞的库** — 必要时给出风险评估与替代方案。
35. **禁止在业务层深度耦合第三方底层 API** — 对关键能力（日期、请求、存储）做轻量封装。
